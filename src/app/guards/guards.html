Angular Route Guards

Control navigation before a route opens.

Route Guards help Angular decide whether a user can enter or leave a route.

⚠️ Route Guards control navigation in the browser. Real security permissions must also be checked by the backend.

02 · Types

Types of Route Guards

CanActivate

"Can the user enter this route?"

Example: a user must be logged in to open the Dashboard.

User→CanActivate→Dashboard
Logged in → AllowedLogged out → Blocked

CanActivateChild

"Can the user enter a child route?"

Example: only admins can open pages inside an Admin section.

Admin→CanActivateChild→Child Route
/admin (parent route)
/admin/users/admin/settings

CanDeactivate

"Can the user leave this route?"

Example: warn the user before leaving a form with unsaved changes.

Edit Form→CanDeactivate→Another Page
@if (leaveStep() === 'confirm') {
You have unsaved changes. Leave anyway?
} @if (leaveStep() === 'left') {

✅ No unsaved changes, navigation allowed.

} @if (leaveStep() === 'stayed') {

✋ Navigation cancelled. You stayed on the form.

}

CanMatch

"Can this route configuration be matched?"

Example: match an admin route only when the user has the required role.

Requested URL→CanMatch→Route Match↪ Try Other Routes

If CanMatch returns false, Angular can try another matching route.

03 · Code

How Guards work

Angular runs the Guard before completing the route navigation.

  • true → Allow navigation.
  • false → Block navigation.
  • UrlTree or RedirectCommand → Redirect navigation.
{{ guardCode }}

Route Guards control navigation, not backend security.

  • Guards can allow or block navigation.
  • Different Guards handle different navigation situations.
  • Always enforce real permissions on the server.
